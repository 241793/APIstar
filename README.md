
## 接口分发（统一网关）

所有上架接口按定义的路径直接调用，例如：

```
GET http://127.0.0.1:8000/svc/time          # 免登录内置服务，浏览器可直接打开
GET http://127.0.0.1:8000/svc/weather?city=上海   # 需密钥接口
curl -H "Authorization: Bearer sk-prod-****" "http://127.0.0.1:8000/svc/weather?city=上海"
```

- **免登录（open）**：无需任何凭证，任何人可调用
- **需登录（login）**：请求头携带专属 token（即用户在控制台「我的密钥」创建的 API Key），支持 `Authorization: Bearer <key>` 或 `X-API-Key: <key>`
- 每次网关调用自动写入调用日志（真实 IP / 真实耗时 / 调用方），并累计接口调用量

## 四类接口形态

| 类型 | 说明 | 示例 |
|------|------|------|
| 内置服务 | 平台预置的真实服务，管理员从模板一键上架 | 时间查询、UUID 生成、天气查询、数据校验等 8 个 |
| 插件接口 | 管理员在线编写 Python `handler(query, body, ip)`，**子进程沙箱执行**（超时 8s 自动终止），**可安装并使用第三方依赖**（见下），保存即上架分发 | 字数统计、强密码生成器、BMI 计算、二维码生成 |
| 外部接口 | 配置第三方上游地址（可附带上游鉴权头 JSON），网关**实时转发**并回传原始响应（自动兼容代理/直连网络） | 第三方一言 |
| 自定义接口 | 定义参数规范与 Mock 响应，网关按定义返回 | 用户登录、订单查询等业务接口 |

每个接口还可配置**限流（次/分钟）**：网关按「接口 + 调用方」滑动窗口计数，超出返回 `429 Too Many Requests`，并在接口文档中向用户展示限速规则。

## 通知与维护模式

管理端「通知与维护」页（运营分组）：

- **平台通知**：发布/编辑/启停/置顶/删除，三级样式（📢 通知蓝 / ⚠️ 注意黄 / 🚨 重要红）。
  用户端控制台顶栏以通知条展示（多条 8 秒轮播，点击查看全部），每 30 秒自动刷新
- **维护模式**：一键开启/关闭，可自定义维护文案。开启后：
  - 普通用户的控制台全部操作返回 503，页面显示全屏维护遮罩（30 秒轮询自动检测恢复）
  - 网关**所有接口**（含密钥调用）返回 503
  - 管理员仍可登录管理端操作（以便关闭维护）；登录与官网门户不受影响

## 在线更新（管理员）

管理端「系统设置 → 🆙 在线更新」：从 GitHub Release 下载更新包，自动备份 → 替换 → 装依赖 → 重启。

**发布更新包**（推荐用内置脚本一键生成）：

```bash
python build_release.py --set-version 1.0.1   # 改版本号并打包
# 或： python build_release.py                # 按当前 apistar/VERSION 打包
```

脚本会：只打包更新器白名单内的文件（自动排除 `__pycache__` / `data.db` / `backups` 等运行时产物）→
生成 `dist/apistar-update.zip` → 用线上更新器做一次**自检**（确保包能被接受）→ 输出 SHA256 与发布步骤。

然后在 GitHub 仓库创建 Release（tag 如 `v1.0.1`，**与包内 VERSION 一致**），上传 `apistar-update.zip` 作为资产。

**使用**：填 owner / repo / tag（留空为 latest，私库可填 token）→ 检查更新 → 应用更新。
全程状态与日志实时展示；自动备份到数据目录 `backups/`（保留 5 份），失败自动回滚，可手动「↩ 回滚」。
Docker 下代码挂载在 `apistar-code` 卷，更新后容器自动重启不丢代码；`APISTAR_FORCE_SYNC_IMAGE=1` 可用镜像代码重置卷。

## 系统设置与数据库

管理端「系统设置」页（运营分组）：

- **运行参数**：签到奖励区间（min~max，签到时随机落值）、注册赠送、站点名、签到防爬模式（签名+滑块/仅签名/仅滑块/关闭）。保存即时生效（多 worker 15 秒内同步）
- **数据库管理**：支持 **SQLite（默认）与 MySQL 双引擎**。填入连接参数可一键「测试连接」；「迁移数据并切换」执行全量迁移（建表 → 分批搬运 → 行数校验），引擎配置持久化，重启服务后生效，原库保留作备份。已按引擎适配 SQL 方言（UPSERT / 自增 / 文本类型 / 占位符自动转换）

## 签到防爬

签到接口默认要求双重验证（可在系统设置中调整强度）：

1. **挑战签名**：前端先取一次性 challenge（30 秒过期），提交 `sign = SHA-256(challenge|token)`。
   token 是登录凭证，爬虫直连拿不到；challenge 一次性消费，抓包重放无效
2. **滑块行为验证**：拖动滑块产生轨迹，后端校验拖动距离、耗时区间、匀速机器人特征（相邻时间差完全一致则拒绝）

## 积分系统

每个需密钥接口可设置**积分消耗（次）**，免登录接口不可计费（自动置 0）。

- **扣费规则**：仅 2xx 成功调用扣费；401/403/404/429/5xx 均不扣。余额不足前置拦截，返回 `402 Payment Required`（附余额与定价说明）
- **获取积分**：每日签到（默认 +20，`APISTAR_SIGNIN_REWARD`）、新用户注册赠送（默认 100）、管理员充值
- **扣费原子性**：`UPDATE … WHERE credits>=cost` 条件更新，并发调用不会扣成负数；流水（`points_logs`）与余额同事务写入，永远一致
- **用户端**：顶栏余额徽章、「我的积分」页（签到按钮 + 流水）；市场卡片与详情抽屉显示"X 分/次"
- **管理端**：积分管理页 —— 全平台总量/累计发放/累计消耗/计费接口数 4 项统计、用户余额排行、手工充值/扣减（写审计）、全平台流水

## 插件依赖管理

插件默认只能使用标准库（`json` / `re` / `math` / `random` / `datetime` / `collections` 等）。
需要第三方包时：**插件管理 → 📦 依赖管理**安装，再在插件编辑的「依赖声明」中填写包名。

- 依赖**全局安装一次**，所有插件共用；安装走后台线程，前端自动轮询进度
- 包名做严格校验，拒绝 URL / 本地路径 / 版本限定符 / `-r` `-e` 等安装形式，用参数列表调用 pip（无 shell 注入面）
- 沙箱采用**受控导入**：
  - `os` / `sys` / `subprocess` / `socket` / `pickle` 等系统模块始终禁止插件直接使用
  - 已声明的依赖及其**间接引用**（如 requests 内部引 urllib3）自动放行
  - 默认「宽松」：本机已装的第三方包可直接 import；设 `APISTAR_STRICT_DEPS=1` 收紧为**必须先声明**
- 安装超时由 `APISTAR_PIP_TIMEOUT` 控制（默认 300s，装 numpy/pandas 可放宽）
- Docker 部署时依赖装进镜像层；如需持久化依赖，把 `site-packages` 也挂卷

- **接口市场**：按分类/关键词浏览，卡片带**接口图标**（管理员可配置）并标注类型与鉴权方式；详情抽屉含接口文档（真实调用地址、鉴权说明、参数表、响应示例、curl，**代码块支持一键复制**）与**在线测试**（向真实网关发起调用，需密钥接口自动选择专属 token）

### 权限与安全

- Bearer Token 登录鉴权，前端路由守卫 + 后端角色校验
- 管理端接口要求 `admin` 角色；用户端数据按账号隔离
- **密码策略**：至少 8 位 + 字母/数字/符号中至少两类 + 常见弱密码黑名单（前后端一致校验）
- **密码存储使用 PBKDF2-HMAC-SHA256 加盐哈希（12 万轮）**；旧库遗留的裸 SHA-256 密文仍可登录，登录成功后自动升级为新格式
- **登录防爆破**：连续失败 5 次锁定账号 10 分钟（提示剩余尝试次数）
- **会话持久化**：登录会话写入 SQLite，服务重启不掉线；滑动有效期 72 小时，续期写库按 10 分钟节流
- **请求体大小限制**：网关拒绝超过 `APISTAR_MAX_BODY_BYTES`（默认 1MB）的请求体，返回 413
- **分页上限**：所有列表接口单页最多 `APISTAR_MAX_PAGE_SIZE`（默认 100）条，防止单请求拖全表
- **参数类型校验**：网关按接口声明的 `integer/number/boolean` 校验入参，类型不符返回 400
- **审计留痕带真实 IP**：管理员关键操作记录操作人、动作、对象与来源 IP
- 插件执行于独立子进程（受限命名空间 + 超时终止）；注意这是演示级隔离，生产环境请用容器/函数计算等强隔离方案

### 运维能力

- **健康检查** `GET /health`：返回服务与数据库状态、活跃会话数（无需鉴权，供监控探针使用）
- **操作审计**（管理端「操作审计」页）：登录、接口/分类/用户的增删改、密码修改、日志清理等关键操作全量留痕，可搜索
- **调用日志治理**：日志页显示总量，一键清理 N 天前日志（建议先导出 CSV 留存）
- **真实 IP**：网关按 `X-Forwarded-For` → `X-Real-IP` → 直连地址的顺序取调用方 IP，反代部署下限流与日志归属正确

## 接口路径与参数

- 网关支持**路径参数**接口，如 `/api/v1/user/{user_id}`，实际请求 `/api/v1/user/10241` 即可命中，
  路径参数会一并注入参数集合供 Mock / 内置服务使用
- 新建或修改接口时会检测**路径冲突**（如已存在 `/a/{id}` 时新建 `/a/detail` 会被拦截），避免网关匹配歧义
- **接口图标**：每个接口可配置一个 emoji 图标（预设 50+ 常用图标或自定义粘贴），
  展示于管理列表、插件卡片、市场卡片、详情抽屉与导出的 HTML 文档；存量接口按路径关键词自动回填

## 部署

### 本地 / 服务器直接运行

```bash
pip install -r requirements.txt
python app.py                          # 单 worker
APISTAR_WORKERS=4 python app.py        # 多 worker（默认已用 sqlite 限流后端共享配额）
```

环境变量：`APISTAR_HOST` / `APISTAR_PORT` / `APISTAR_WORKERS` / `APISTAR_DB` /
`APISTAR_RATE_BACKEND=memory|sqlite` / `APISTAR_SESSION_TTL_HOURS` / `APISTAR_LOGIN_MAX_FAILURES` /
`APISTAR_MAX_PAGE_SIZE` / `APISTAR_MAX_BODY_BYTES` / `APISTAR_MIN_PASSWORD_LEN` /
`APISTAR_PLUGIN_TIMEOUT` / `APISTAR_PIP_TIMEOUT` / `APISTAR_STRICT_DEPS`。

### Docker

```bash
docker compose up -d          # 构建并启动，数据持久化在 apistar-data 卷
curl http://localhost:8000/health
```

- 容器内以非 root 用户运行，SQLite 数据挂卷 `/data`
- 默认 2 worker：SQLite WAL 模式支撑多进程并发；限流窗口经 `rate_counters` 表跨 worker 共享
- 反向代理（Nginx/Caddy）下网关自动识别 `X-Forwarded-For`，限流与日志归属真实 IP
